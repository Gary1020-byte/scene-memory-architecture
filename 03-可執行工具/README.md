## 五秒上手

```bash
cd 03-可執行工具

# 看示範工作台長什麼樣
node 場景記憶.mjs list --root ../04-模板/示範工作台

# 跑一次自我驗收（會故意弄壞再還原）
bash 反例驗收.sh

# 檢查所有 markdown 連結是否有效
node 檢查連結.mjs

# 換會話：前置檢查（能不能換）＋ 換完自檢（三處有沒有同步）
node 換會話.mjs 計畫 --root ../04-模板/示範工作台 --場景 示範場景
node 換會話.mjs 檢查 --root ../04-模板/示範工作台 --場景 示範場景

# 會話檔案層：聊天全文的歸處
node 會話檔案.mjs 檢查 --root ../04-模板/示範工作台
```

## 這個板塊的設計主張

> **「該失敗時會失敗」是一個可以證明的東西，不是一句口號。**

所以這裡不放「教學文件」，放的是：

1. **一支真的能擋下問題的工具**（退出碼正確、訊息具體）
2. **一份真的會把它弄壞的驗收腳本**（10 條反例，全過）
3. **一份規則單一來源**（改紅線只改一個地方）

> 一個永遠回 0 的檢查器，比沒有檢查器更危險——
> 它讓人以為有防護，其實沒有。

---

## 三條不變量

| 不變量 | 意思 |
|---|---|
| **工具不寫正文** | 場景記憶的正文永遠是人寫的。工具只做骨架、補缺、蓋章、檢查 |
| **交接不覆寫** | 只「缺才補」。覆寫 §₀ 會洗掉進度，比沒交接更糟 |
| **規則不硬編碼** | 紅線等規則讀 `交接規則.json`，工具與腳本共用一份 |
