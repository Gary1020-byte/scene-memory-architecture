# 校驗工具

> 兩支**可執行**的校驗工具：
> `場景記憶.mjs`（場景結構）與 `工作流校驗.mjs`（工作流定義）。
> 兩支都**只讀不寫**（除了 `init`／`stamp`／`交接` 這三個本來就要寫的命令），
> 而且**不依賴任何 npm 套件**。

---

## 一、怎麼用

```bash
cd 03-可執行工具

# 一覽：每個場景缺什麼
node 場景記憶.mjs list --root <工作台根>

# 建骨架 + 三份文件
node 場景記憶.mjs init --場景 場景甲 --root <工作台根>

# 重生成 身份卡 + 場景畫像
node 場景記憶.mjs stamp --場景 場景甲 --root <工作台根>

# 交接：歸檔舊版 + 補 §₀ + stamp + 登記索引
node 場景記憶.mjs 交接 --場景 場景甲 --root <工作台根>

# ★ 全檢
node 場景記憶.mjs check --場景 場景甲 --root <工作台根>

# 全場景檢查
node 場景記憶.mjs check --all --root <工作台根>
```

`<工作台根>` 不給也行——工具會往上找，或讀環境變數 `DSH_WORKBENCH_ROOT`。

### 換會話（前置檢查 ＋ 三處同步自檢）

```bash
# 前置檢查：能不能換？＋ 印出引擎端要做的五步
node 換會話.mjs 計畫 --root <工作台根> --場景 <場景名>

# 換完自檢：三處會話 id 一致 ＋ check 通過 ＋ §₀ 沒超紅線
node 換會話.mjs 檢查 --root <工作台根> --場景 <場景名> [--新會話id <id>]
```

> **「三處」＝場景配置 sessionId ／ 身份索引會話 id 欄 ／ §₀ 交接署名。**
> 少同步一處的症狀都是「切場景像換了個人」⇒ 工具一次對三處，不要靠症狀猜。

### 會話檔案層（聊天全文的歸處）

```bash
# 從引擎匯出檔抽出（自動重建索引）
node 會話檔案.mjs 抽出 --root <工作台根> --引擎端 <匯出.json> --場景 <場景名>

# 重建索引 / 自檢 / 查
node 會話檔案.mjs 索引 --root <工作台根>
node 會話檔案.mjs 檢查 --root <工作台根>
node 會話檔案.mjs 列出 --root <工作台根> --場景 <名>
node 會話檔案.mjs 列出 --root <工作台根> --關鍵詞 <字>
```

> **引擎端的匯出格式**（repo 定介面，不定引擎怎麼匯）：
> 一個 JSON，欄位 `會話id`／`會話名`／`場景id`／`開始時間`／`訊息[]{角色,文字}`。
> 角色收中英兩種寫法。

### 工作流校驗與執行（另外兩支工具）

```bash
# 檢查工作台裡所有工作流定義
node 工作流校驗.mjs --root <工作台根>

# 只檢查某一份
node 工作流校驗.mjs --root <工作台根> --檔 磁碟體檢與清理

# 直接檢查一個檔案
node 工作流校驗.mjs --檔案 /path/to/某工作流.yaml
```

**工作流執行器**（`工作流執行.mjs`）——讓場景真的串成一條線跑：

```bash
# 啟動（預檢不通過就拒絕啟動）
node 工作流執行.mjs start --root <工作台根> --工作流 <id>

# 推進下一跳（產生派單檔）
node 工作流執行.mjs step --root <工作台根> --run <run-id>

# 收回執（★ 驗收：不合格就擋下並就地停）
node 工作流執行.mjs 回執 --root <工作台根> --run <run-id> --回執 <回執檔>

# 修好之後接回去
node 工作流執行.mjs resume --root <工作台根> --run <run-id>

# 門檻確認通過，繼續下一跳
node 工作流執行.mjs resume --root <工作台根> --run <run-id> --門檻通過

# 看狀態
node 工作流執行.mjs status --root <工作台根>
```

**回執校驗**（`回執校驗.mjs`）——單獨用：

```bash
node 回執校驗.mjs --root <工作台根> --場景 <場景名> --回執 <回執檔>
```

它檢兩件事：
1. 回執有沒有三件套（差異集合 · 可累積物 · 下一棒）
2. ★ **那些可累積物有沒有真的落地到場景記憶**（§五 決策與坑或專屬技能裡找得到）

> 第 2 點是重點：**只在回執裡寫了不算數**，必須在場景記憶裡找得到。
> 這是「累積真的發生」的機械證據。

**這個版本是離線執行器**：它不真的呼叫引擎，而是把每一步該做什麼寫成檔案並推進狀態機。
這是刻意的——**引擎中立**。引擎專用版只要把「產生派單」換成「真的派出去」即可，
狀態機與驗收邏輯完全沿用。

#### 端到端驗收

```bash
bash 工作流驗收.sh
```

12 項：預檢擋人 · 缺可累積物被擋 · 沒落地被擋 · 落地後通過 ·
可累積物跨場景傳遞 · 門檻攔截 · 門檻確認後才繼續。

### 工作流校驗（另一支工具）

```bash
# 檢查工作台裡所有工作流定義
node 工作流校驗.mjs --root <工作台根>

# 只檢查某一份
node 工作流校驗.mjs --root <工作台根> --檔 磁碟體檢與清理

# 直接檢查一個檔案
node 工作流校驗.mjs --檔案 /path/to/某工作流.yaml
```

它會找這些位置（取第一個存在的）：

```
<工作台根>/工作流/
<工作台根>/場景/_共享記憶/工作流/
<工作台根>/共享/工作流/
```

**擋什麼**：缺必要欄位、步驟缺「場景／目的／判據」、「需確認」不是 true/false、
「失敗策略」不是合法值、步驟不是清單。
**只提示**：判據太短（可能不可驗證）、完全沒有門檻、每步都設門檻、未知欄位。

> 它解析的是本專案定義的那個**受限 YAML 子集**（純量、`-` 清單、兩層縮排）。
> 遇到看不懂的結構會**明確報錯**而不是猜錯——這是刻意的：
> 一個會默默猜錯的檢查器，比沒有檢查器更危險。

### 記憶根怎麼找

```
環境變數 DSH_SCENE_MEMORY
  → <工作台根>/場景
  → <工作台根>/引擎數據/.dsh/場景記憶
```
取第一個**存在且是目錄**的。

> **這個候選鏈是重點，不是細節。**
> 曾經兩個腳本各自硬編碼路徑，結果訊息寫進了舊看板、收件方根本收不到，
> 而且**表面完全看不出來**（見[已知裂縫 #3](../02-落地實作/四-已知裂縫與待修.md)）。
> 統一路徑解析是那個 bug 的架構級修法。

### 身份索引怎麼找

```
場景/_場景身份索引.md
  → 外壳/scenarios/_場景身份索引.md
```

> `外壳/` 是本機工作台的**實際目錄名**（原樣保留，含其簡體字形）——
> 這是底層引擎的既有慣例，不是錯字。工具取第一個**存在的**路徑，
> 所以你的工作台用哪個名稱都行；`場景/_場景身份索引.md` 是本工具建議的新位置。

## 二、退出碼

| 碼 | 意思 |
|---|---|
| `0` | 通過（可能仍有警告） |
| `1` | **有問題，已擋下** |
| `2` | 用法錯誤 |

> 退出碼要對，因為這工具會被別的腳本、cron、CI 呼叫。
> **一個永遠回 0 的檢查器，比沒有檢查器更危險。**

## 三、check 檢查什麼

### 擋（exit=1，結構性問題）

| 檢查 | 訊息 |
|---|---|
| 缺必要檔案 | `缺檔案 場景私有記憶.md` |
| 缺必要目錄 | `缺目錄 專案記憶/` |
| **場景邊界失效** | `場景目錄缺少 .git（場景邊界失效 ⇒ 專屬技能不會被載入，且症狀不明顯）` |
| 身份索引無此卡 | `身份索引裡沒有這張場景卡：<名>` |
| 定位卡欄位空 | `身份索引的定位卡欄位是空的` |
| 定位卡不存在 | `定位卡不存在：<路徑>` |
| 卡指紋過期 | `卡指紋過期（卡已改，跑 stamp）<fp>…≠<real>…` |
| 身份卡無指紋 | `身份卡裡沒有卡指紋（跑 stamp 重蓋）` |
| 缺核心職責 | `缺「## 核心職責」塊（場景私有記憶必填）` |
| 職責條數不足 | `核心職責只有 2 條（至少 3 條）` |
| §₀ 缺小節 | `§₀ 缺小節 ### 4) 下一步 / 卡點` |
| §₀ 超紅線 | `§〇 5000 B 超 4 KB（紅線 4096）` |
| 缺 §₀ 頭 | `缺 §〇 交接頭（## §〇）` |

### 只警告（exit=0）

| 檢查 | 訊息 |
|---|---|
| 主檔案超標 | `主檔案 26.0 KB 超 25 KB（紅線，搬舊內容進 歸檔/ 並留指針）` |
| 專案記憶超標 | `專案記憶 X.md 9.0 KB 超 8 KB` |
| 專案表過期 | `當前專案表寫「暫無」，但專案記憶有 3 份（表需更新）` |
| 下一步為空 | `第 4 小節 下一步/卡點 為空` |
| 舊版 §0 頭 | `用的是舊 §0 頭（## 〇、當前交接），建議改為 ## §〇` |

> **分清楚「擋」與「警」**：
> 擋 = 結構性錯誤，繼續下去一定壞 ⇒ fail-closed。
> 警 = 品質問題，可能只是忘了更新 ⇒ 讓人自己判斷。

## 四、反例驗收（自我驗收）

```bash
bash 反例驗收.sh
```

這個腳本會**故意弄壞**示範場景，逐一驗證工具會擋下。輸出：

```
═══ 反例驗收：校驗工具必須能證明「該失敗時會失敗」 ═══

【V8】正常資料應該通過（期望 exit=0）
  ✓ 正常場景全部通過
【V1】§₀ 灌爆 4 KB 紅線（期望 exit=1）
  ✓ §₀ 超紅線被擋
【V2】刪掉「### 4) 下一步 / 卡點」（期望 exit=1）
  ✓ §₀ 缺小節被擋
【V3】改定位卡但沒重蓋身份卡 ⇒ 指紋過期（期望 exit=1）
  ✓ 卡指紋過期被擋
【V5】刪掉「## 核心職責」整塊（期望 exit=1）
  ✓ 缺核心職責被擋
【V6】核心職責只寫 2 條（期望 exit=1）
  ✓ 核心職責條數不足被擋
【V9】場景目錄缺 .git（期望 exit=1）
  ✓ 缺 .git 被擋
【V10】身份索引裡沒有這張場景卡（期望 exit=1）
  ✓ 索引無此卡被擋
【V11】定位卡欄位指向不存在的檔（期望 exit=1）
  ✓ 定位卡不存在被擋
【V7】專案記憶有份但當前專案表寫「暫無」（期望 exit=0 + 警告）
  ✓ 表格過期只警告不擋（exit=0）

═══ 結果：10 通過，0 失敗 ═══
```

> ⚠️ **只看「正常情況通過」不算驗證。**
> 一個從不報錯的檢查器，比沒有檢查器更危險——
> 它會讓人以為有防護，其實沒有。

## 五、規則單一來源

紅線、小節清單、指紋長度都寫在 **`交接規則.json`**，工具讀它，不硬編碼。

```json
{
  "sec0MaxBytes": 4096,
  "mainMaxBytes": 25600,
  "projectMaxBytes": 8192,
  "fingerprintLength": 16,
  "sec0Subsections": ["### 1) 上次交接", "..."],
  "dutyHeading": "## 核心職責",
  "dutyMinItems": 3
}
```

工具的搜尋順序：
```
工具同目錄/交接規則.json
  → <工作台根>/交接規則.json
  → 04-模板/交接規則.json
  → （都沒有 ⇒ 內建預設）
```

> **改紅線只改這一個檔案。**
> 改了之後記得同步三處：規則檔、工具內建預設（若有）、文件裡提到的數字。

## 六、接到自己的目錄

```bash
# 1) 你的工作台長這樣
<我的工作台>/
└── 場景/
    ├── _場景身份索引.md
    └── <我的場景>/
        ├── .git/          ← 場景邊界（記得 git init）
        ├── 定位卡.md
        └── 場景私有記憶.md

# 2) 跑
node 場景記憶.mjs list --root <我的工作台>
node 場景記憶.mjs init --場景 <我的場景> --root <我的工作台>
node 場景記憶.mjs stamp --場景 <我的場景> --root <我的工作台>
node 場景記憶.mjs check --場景 <我的場景> --root <我的工作台>
```

**注意**：
- 場景目錄**必須有 `.git/`**（場景邊界），否則 check 會報錯——
  這是故意的：沒有邊界，專屬技能不會被載入，而症狀不明顯。
- 身份索引的欄位數要對齊（7 欄）：
  `場景id | 面板id | 面板標題 | 會話名 | 會話id | 定位卡 | 主技能`

## 七、這工具**不**做什麼

| 不做 | 為什麼 |
|---|---|
| 不寫場景記憶的正文 | 記憶是**人寫**的。工具只做骨架、補缺小節、蓋章、檢查 |
| 不動 §₀ 已有內容 | 交接只「缺才補」，不覆寫——覆寫會洗掉進度，比沒交接更糟 |
| 不刪任何東西 | 工具只新增與檢查。刪除是有破壞性的操作，不該由校驗工具做 |
| 不碰身份卡/場景畫像的手改 | 這兩個由工具全量重寫，手改會被還原 |
