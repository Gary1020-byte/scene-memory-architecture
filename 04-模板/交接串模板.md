# 交接串模板

> **每一跳的可累積物往下傳的載體。**
> 工作流裡資訊在跳之間流動，靠的就是它——不是靠場景之間互相傳話。

---

## 一、模板

```markdown
# 交接串 · <工作流名稱>

> 每一跳的可累積物往下傳的載體。下一跳的派單會引用這裡的內容。

## 步驟 1 的可累積物

- <做法 / 判準：下次該怎麼做>
- <坑：下次會踩什麼>

## 步驟 2 的可累積物

- <做法 / 判準>

## 步驟 3 的可累積物

（尚未執行）
```

---

## 二、它是什麼、不是什麼

| 是 | 不是 |
|---|---|
| **跨跳傳遞的通道**——下一跳的派單會把上一跳的可累積物帶進去 | 共享層的公告（那是看板的事） |
| 每次執行一份（跟 run 走） | 工作流定義的一部分（那是計畫） |
| 內容來自回執的「可累積物」小節 | 人工整理的摘要 |

> **它跟場景記憶的差別**：場景記憶是**那個場景的**累積（跨 run 存在）；
> 交接串是**這一次工作流裡**的傳遞（run 結束就封存）。
> 兩者都要有——場景記憶讓「下次做同類活」變快，交接串讓「這條鏈往下走」接得上。

---

## 三、為什麼不直接讓場景 A 寫進場景 B 的記憶

因為**場景主權**：每個場景只寫自己的記憶。

跨場景的傳遞走兩條路，都不破主權：

```
① 交接串（工作流內，run 私有）—— 執行中的接力
② 場景記憶 §五（跨 run 存在）—— 長期的累積
```

前者是「這條鏈現在走到哪」，後者是「這類活我學到了什麼」。
**不要混用**——混了就會出現「A 的東西寫進 B 的記憶，B 也不知道那是誰的」。

---

## 四、寫之前確認

1. 每一步都有對應的小節嗎？（沒執到的先寫「（尚未執行）」）
2. 內容是從回執的「可累積物」小節來的嗎？（不是自己另外編一套）
3. 有沒有把狀態資訊（數字、進度）也塞進來？**那些屬於差異集合，不屬於這裡。**
