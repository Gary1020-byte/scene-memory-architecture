# 執行狀態模板

> 這是**一次執行**的私有狀態，不是計畫。
> 工作流**定義**在共享層（`工作流/<id>.yaml`），這份是「這一次跑到哪」。
>
> 混在一起 ⇒ 執行狀態會分裂成多份，沒有人讀得到權威版本。

---

## 一、模板

```markdown
# 執行狀態 · <工作流名稱>

> 這份檔案是**這一次執行**的私有狀態（不是計畫）。工作流定義在共享層。
> 中途關掉、當機、換人接手 ⇒ 靠這份檔案接得上。

- 工作流：<工作流名>
- run id：<工作流名>-<日期>-<序號>
- 啟動時間：<YYYY-MM-DD HH:MM:SS>
- 更新時間：<YYYY-MM-DD HH:MM:SS>
- 狀態：<執行中 / 等門檻 / 已停 / 已完成>
- 目前步驟：<N>

## 步驟進度

| # | 場景 | 狀態 | 回執 |
|---|---|---|---|
| 1 | <場景名> | <待執行 / 執行中 / 已完成> | <回執檔名> |

## 卡點

- <無 / 卡在哪、等什麼>

## 下一個動作

<具體到可以直接照著做的那一句>
```

---

## 二、狀態的四個值

| 狀態 | 意思 | 怎麼離開 |
|---|---|---|
| **執行中** | 正常跑 | 下一跳完成後自動前進 |
| **等門檻** | 這一步是門檻，跑完停下等人 | `resume --門檻通過` |
| **已停** | 某步失敗或回執不合格（fail-closed） | 修好後 `resume` |
| **已完成** | 走完全部步驟 | — |

---

## 三、卡點要寫清楚三件事

```
- 卡在哪：<哪一步、哪個檔案>
- 等什麼：<等誰做什麼 / 缺什麼資訊>
- 為什麼：<一句話>
```

> 只寫「卡住了」等於沒寫。下一個人（或三個月後的你）看到「卡在哪、缺什麼」才能接。

---

## 四、這個目錄的結構

```
執行/<run-id>/
├── 執行狀態.md      ← 本檔案
├── 交接串.md        ← 每一跳的可累積物往下傳的載體
├── 工作流.yaml      ← 啟動時的定義快照（改了定義不影響這一次）
└── 回執/
    ├── 派單-1.md    ← 每一跳的派單
    ├── 派單-2.md
    ├── 回執-1.md   ← 收回的回執副本
    └── 回執-2.md
```

> **為什麼要存工作流快照**：定義改了之後，正在跑的那一次該用哪一版？
> 答案是「啟動時那一版」——所以快照必須跟著 run 走。

## 五、寫之前確認

2. 已完成的步驟，回執檔都在 `回執/` 裡嗎？
3. 卡點寫清楚「卡在哪、等什麼」了嗎？
