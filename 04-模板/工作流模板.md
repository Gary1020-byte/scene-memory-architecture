# 工作流模板

> 工作流定義住在共享層第五塊板：`共享/工作流/<工作流id>.yaml`
> 拷一份改，改完跑校驗。

---

## 一、最小可用（只有一步也能跑）

```yaml
id: 磁碟體檢與清理
名稱: 磁碟體檢 → 清理 → 報告
版本: 1
步驟:
  - 場景: 場景丙
    目的: 找出可清理的項目
    判據: 列出可釋放 ≥ 1 GB 的項目，每項標明路徑與大小
    落盤: 場景/場景丙/專案記憶/磁碟體檢-<日期>.md
    需確認: false
失敗策略: 停在原地等人
```

## 二、完整骨架

```yaml
id: 磁碟體檢與清理
名稱: 磁碟體檢 → 清理 → 報告
版本: 1
說明: 每季檢查磁碟，清理可釋放空間，最後出一份報告
入口: 磁碟體檢

步驟:
  - 場景: 場景丙
    目的: 找出可清理的項目
    判據: 列出可釋放 ≥ 1 GB 的項目，每項標明路徑與大小
    落盤: 場景/場景丙/專案記憶/磁碟體檢-<日期>.md
    需確認: false

  - 場景: 場景丙
    目的: 清理
    判據: 實際釋放 ≥ 1 GB，並在回執列出刪了什麼
    落盤: 場景/場景丙/專案記憶/磁碟清理-<日期>.md
    需要: 磁碟體檢的清理清單
    需確認: true

  - 場景: 場景甲
    目的: 出報告
    判據: 報告落盤，且首行寫在共享看板
    落盤: 場景/場景甲/專案記憶/磁碟報告-<日期>.md
    需要: 清理結果
    需確認: false

失敗策略: 停在原地等人

分岔:
  - 當: 步驟1 未找到 ≥1GB 可清理
    則: 跳過步驟2，直接進步驟3
```

---

## 三、欄位說明

| 欄位 | 必填 | 作用 | 缺了會怎樣 |
|---|---|---|---|
| `id` | ✅ | 工作流識別 | 執行狀態找不到對應 |
| `名稱` | ✅ | 人看的名字 | — |
| `版本` | ✅ | 改版時遞增 | 不知道跑的哪一版 |
| `步驟[].場景` | ✅ | 這一跳由哪個場景執行 | 沒有對象 |
| `步驟[].目的` | ✅ | 這一跳要做什麼 | 像一句願望 |
| `步驟[].判據` | ✅ | **什麼算這步做完**（可驗證） | 回執無從判定真假 |
| `步驟[].落盤` | ✅ | 產出寫到哪 | 產出散落，下一跳接不到 |
| `步驟[].需要` | — | 這一跳要吃上一跳的什麼 | 資訊斷在跳之間 |
| `步驟[].需確認` | — | 是不是門檻 | 不可逆操作被自動跑掉 |
| `失敗策略` | ✅ | 壞了怎麼辦 | 斷在半路沒人知道 |
| `分岔` | — | 條件式路徑 | 只能走直線 |

## 四、門檻怎麼標

**只在三種情況設 `需確認: true`**：

| 判準 | 例子 |
|---|---|
| **不可逆** | 刪檔、對外發送、發布 |
| **要花不可回收的資源** | 錢、對外配額、對第三人的通知 |
| **產出會被下游當成事實** | 刪完的清單會被後續步驟拿去刪東西 |

**中間步驟不要設門檻。** 體檢、產草稿、整理清單這些可重跑的步驟，
設了門檻只會讓工作流變成逐跳確認——那樣就失去意義了。

> **安全不該靠「每步都問人」，該靠「壞了就停」。**
> 逐跳確認是把停的決定權交給人每次都要行使；只在門檻停，是只在真正需要判斷時打斷。

## 五、執行狀態在哪

```
<工作台根>/執行/<run-id>/
├── 執行狀態.md      ← 跑到哪、卡在哪、等什麼
└── 交接串.md        ← 每一跳的可累積物往下傳的載體
```

**不在共享層**（那是計畫），**不在場景私有層**（那是某個場景的記憶）。
一條工作流可以有多個 run；每個 run 一份私有狀態。

---

## 六、寫之前確認三件事

1. **每一跳的 `判據` 是不是可驗證的？** 「清理乾淨」不是判準；
   「實際釋放 ≥ 1 GB，並在回執列出刪了什麼」才是。
2. **不可逆的那一跳，設門檻了嗎？**
3. **每一跳的 `需要`，上一跳真的產得出來嗎？** 上一跳的可累積物要寫得夠清楚。
