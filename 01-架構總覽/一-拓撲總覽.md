## 二、連線逐條說明

| # | 連線 | 從 → 到 | 幹嘛 | 破了會怎樣 |
|---|---|---|---|---|
| **C1** | 注入 | L0 → 每輪對話 | 全域鐵律每輪自動注入 | 注入層變長 ⇒ 每輪多付 token |
| **C2** | 只讀本樹 | L2 場景 A → A 的記憶 | 開場讀 §〇 交接 | 跨場景讀取別人的記憶 ⇒ 邊界失效 |
| **C3** | 專案記憶 | 場景 → 自己的 `專案記憶/` | 一專案一份，≤ 8 KB | 專案記憶混進 §〇 ⇒ 開場讀不完 |
| **C4** | 技能可見性 | 引擎 → 專案根的 `.dsh/skills/` | 只掛本場景的技能 | 別的場景技能也看得到 ⇒ 場景不再獨立 |
| **C5** | 派單 | L1 共享層 → 目標場景 | RPC 叫醒 / 檔案留言 | 只送不收 ⇒ 活沒回來 |
| **C6** | 回執 | 目標場景 → L1 共享層 | 結論+證據+路徑+差異集合 | 回執是「一切正常」⇒ 無法驗證 |
| **C7** | 寫入 | L3 工具 → L2/L1 | 工具盖章、補骨架 | 工具路徑寫死 ⇒ **看板分裂** |
| **C8** | 稽核 | L2/L1 → L4 | git log 全在 | 改動無痕 ⇒ 記憶不是資產 |

## 三、一次完整循環

```
 ① 機主一句話
        ↓
 ② 命令台讀路由表（場景 → 場景 id → 觸發詞）
        ↓
 ③ 場景路由命中 ⇒ 四件套派單
        │           └─ 沒命中 ⇒ 交給模型依職責判斷
        ↓
 ④ 通道 A：引擎 RPC（session/prompt）── 把對方叫醒
    通道 B：檔案留言 ── 寫進看板 + 對方 §〇-通知（同時留痕）
        ↓
 ⑤ owner 讀自己的 §〇（知道自己是誰、幹到哪）
        ↓
 ⑥ owner 動手 ⇒ 結論寫進自己的專案記憶
        ↓
 ⑦ owner 回執：結論 + 證據 + 路徑 + 差異集合（≤10 行 / ≤2 KB）
        ↓
 ⑧ 命令台收回執 → 核對 → 回覆機主
        ↓
 ⑨ 收工：覆蓋寫 §〇 → 跑 check → 過了才准換會話 → 舊版進歸檔
```

## 四、三條不能破的線

| 線 | 說明 |
|---|---|
| **每個東西只在一個地方是真源** | 別處只放指針。這條一破，就會出現「看板分裂」「兩份數字打架」 |
| **場景之間只走 L1 共享層** | 不許跨場景直連寫檔。共享層是唯一合法的跨場景通道 |
| **L2 與 L5 分離** | 歸檔只進不改。任何升級都能回滾 |

## 五、與引擎的關係

```
        ┌──────────────────────────────────────┐
        │  引擎（DSH）提供的能力                 │
        │  ───────────────────────────────────  │
        │  · findProjectRoot：.git 劃界 ★       │
        │  · 只載入專案根→cwd 祖先鏈的 AGENTS.md │
        │  · 技能根掛在專案根上                 │
        │  · 會話 / 工作區 / 提示詞 RPC          │
        └──────────────────────────────────────┘
                        ▲
                        │ 這套架構**不重造**引擎，只用它當底座
                        │
        ┌──────────────────────────────────────┐
        │  本架構提供的東西                      │
        │  ───────────────────────────────────  │
        │  · 記憶的文件形態與紅線                 │
        │  · 場景六件套的規格                    │
        │  · 派單四件套與回執判據                 │
        │  · 校驗工具（fail-closed）              │
        │  · 維護手冊                            │
        └──────────────────────────────────────┘
```

> **邊界很重要**：`.git` 劃界是引擎的行為，不是這裡發明的。
> 這套架構做的是**在引擎之上，把記憶從「約定」變成「有契約的檔案」**。
