## 六篇怎麼串起來

```
一-累積 ──────▶ 二-場景 ──────▶ 三-場景記憶
 (為什麼要累積)    (載體長什麼樣)   (記憶怎麼放)
                      │                │
                      └───────┬────────┘
                              ▼
                        四-派單與回執
                     (怎麼派、怎麼收回來、
                      ★怎麼帶累積物回來)
                              │
                              ▼
                        五-工作流
                    (場景怎麼串成一條線)
                              │
                              ▼
                        六-兩套記憶的分工
                     (這一切是「哪一層」的問題)
```

**一句話概括整個板塊：**

> **累積要有載體，載體要能改寫；派單要帶回累積物，回執要能被驗收；串起來要有人看得見。**

---

## 三個紅線（整套架構最硬的規矩）

| 紅線 | 擋住什麼病 |
|---|---|
| **一次派單 ＝ 一條回執** | 活幹完了但對方還不知道 |
| **沒有可累積物的回執 ＝ 這次活白做** | 活幹完了但認識沒累積 |
| **⛔ 只許請求，不許改對方記憶** | 邊界糊掉，稽核失效 |

前兩條是同一族：**做了，但沒留下。**
第三條是所有累積的前提——**累積必須發生在有主權的地方，否則沒有人負責維護它。**

## 如果只讀一篇

讀 [一-累積](一-累積.md)。它是整套架構的主線：
**為什麼能力不該靠模型更聰明，而該靠一個能被改寫的載體。**

其餘五篇都是它的展開——場景是那個載體、場景記憶是它的形狀、
派單與回執是累積的迴圈、工作流是場景的編排。
