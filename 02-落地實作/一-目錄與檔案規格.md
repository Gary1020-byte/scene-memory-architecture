# 一 · 目錄與檔案規格

> 這是**可以直接照抄的規格**。所有檔名、段落標題、欄位都是約定，不是建議。
>
> ⚠️ **範例裡的 `外壳/` 是本機工作台的實際目錄名（原樣保留，含其簡體字形）**。
> 這類目錄名來自底層引擎的既有慣例，**不是錯字，也不需要統一改寫**——
> 改了反而會讓文件與實機對不上。你的工作台若用別的名稱，照你的實際情況改即可；
> 真正需要一致的是**結構**（工具與資料分離、場景各自一個 git 倉庫），不是字形。

---

## 1. 工作台目錄

```
<工作台根>/
├── 場景/                          ← ★ 場景層（每個場景一個獨立 git 倉庫）
│   ├── _共享記憶/                 ← 共享層（L1）
│   │   ├── _場景身份索引.md        ← ★ 單一權威：場景 id ↔ 面板 ↔ 會話 ↔ 定位卡 ↔ 技能
│   │   ├── _跨場景通知.md          ← 跨場景看板（一行一條，最新在上）
│   │   ├── _待辦.md                ← 待辦板（全機唯一落點，同一件只許一行）
│   │   ├── 衝突.md                ← 衝突簿：兩處打架了先登記
│   │   ├── 項目.json              ← 專案清單（路由到各自的記憶檔）
│   │   ├── 索引.md / 索引.json     ← 結構化總索引
│   │   └── areas/<場景>.md        ← 各場景名片頁
│   ├── <場景A>/                   ← ★ 獨立 git 倉庫
│   ├── <場景B>/
│   └── <場景C>/
├── 工具/                          ← 工具層（L3）：可執行、可升級、不放資料
├── 外壳/                          ← 工作台界面（面板、頂欄）
└── 說明/                          ← 給人看的文件
```

> **判據：工具與資料分離。** 升級／換掉工具，不該動到場景記憶。
> 這也是為什麼 `工具/` 放在工作台根、而不是放在某個場景裡。

### 共享層四塊板：各回答一個問題

| 板 | 回答 | 誰寫 | 生命週期 |
|---|---|---|---|
| **跨場景看板** | **發生了什麼**（公告／派單／回執） | 發訊息工具自動寫 | 最新在上；每場景只在自己記憶裡留 ≤ 5 條摘要 |
| **待辦板** | **該做什麼**（全機唯一落點） | 任何場景加一行，同一件只許一行 | 做完刪行；掛起太久搬歸檔 |
| **總索引／身份索引** | **東西在哪**（場景 ↔ 記憶 ↔ 卡 ↔ 技能） | 新建／移動時就登記 | 表格化，單一權威 |
| **衝突簿** | **兩處打架了** | 任何人發現就登記 | 裁決後關閉 |

> **為什麼板要分開**：它們**更新頻率不同**（看板一天幾十條、索引一週幾條）、
> **讀者不同**（看板人人看、索引偶爾查）、**責任不同**（看板誰發誰寫、索引誰建誰登記）。
> 混在一起的結果是：**更新最頻繁的那塊把所有東西都擠沒了**。

### 這個工作台根長什麼樣（實機，2026-11-01）

本機實際跑的是 **3 個場景**：場景甲／場景丁／場景丙，**每個都是獨立的 git 倉庫**。

| 層 | 實機內容 | 實測 |
|---|---|---|
| 場景層 | 3 個場景目錄，各有 `.git/` | 場景邊界 = 專案根 |
| 共享層 | `_共享記憶/`（看板／待辦／衝突／索引／項目表） | 兩塊看板曾分裂（見裂縫 #3） |
| 工具層 | 校驗、建會話、發訊息、派單腳本 | 與資料分離 |
| 稽核層 | 每場景自己的 git 倉庫 | `git log` 全在 |

> 這個架構**不綁死引擎**：`.git` 劃界、技能掛載、指令注入是引擎的行為，
> 你換引擎就要重測那三件事（[三-維護手冊](三-維護手冊.md)任務 E）。

## 2. 場景目錄規格

```
場景/<場景名>/
├── .git/                          ← ★ 場景邊界（引擎靠它判定專案根）
├── AGENTS.md                      ← 場景憲法（只對本場景的會話注入）
├── .dsh/skills/<場景id>/SKILL.md  ← 場景專屬技能（只在本場景可見）
├── 定位卡.md                       ← 場景身分說明書（人寫，是校驗的錨點）
├── 場景私有記憶.md                 ← ★ 記憶真源（人寫）
├── 身份卡.md                       ← 工具生成，⛔ 手改即校驗失敗
├── 場景畫像.md                     ← 工具生成，⛔ 手改即校驗失敗
├── _檔案索引.md                    ← 這個場景有哪些檔案（四態：活／常備／留檔／待清）
├── 專案記憶/<專案id>.md            ← 一專案一份，≤ 8 KB
└── 歸檔/                          ← 舊版快照，只進不改
```

### 各檔案的權限歸屬

| 檔案 | 誰寫 | 改了會怎樣 |
|---|---|---|
| `AGENTS.md` | 人 | 換會話後才生效（每輪注入） |
| `.dsh/skills/` | 人 | 同上 |
| `定位卡.md` | 人 | **指紋失效** ⇒ 必須重跑 `stamp` |
| `場景私有記憶.md` | 人 | §〇 結構錯 ⇒ `check` 報錯 |
| `身份卡.md` | **工具** | ⛔ 手改即校驗失敗 |
| `場景畫像.md` | **工具** | ⛔ 手改即校驗失敗 |
| `_檔案索引.md` | 人 + 工具登記 | —— |

### 六件套 → 檔案對照

「場景六件套」是機制層的概念（見[`二-場景體系`](../00-核心機制/二-場景體系.md)第 2 節），
這裡是它在**檔案層**的樣子——照這張表就能知道少哪一件、補哪一個檔。

| # | 件 | 檔案 | 格式要點 | 缺了會怎樣 |
|---|---|---|---|---|
| 1 | **場景配置** | `<場景id>.json` | `id`／`name`／`description`／`layout`／`theme`／`panels[]`；每個面板有 `id`／`title`／`type`／`col`／`row`／`w`／`h` | 面板裡根本不出現這個場景 |
| 2 | **定位卡** | `定位卡.md` | 六行固定欄位（見第 4 節） | 校驗拿不到指紋 ⇒ `check` 直接擋 |
| 3 | **場景私有記憶** | `場景私有記憶.md` | §〇 五小節 + 核心職責 + §一／§二／§五 | 換會話斷片 |
| 4 | **場景專屬技能** | `.dsh/skills/<場景id>/SKILL.md` | YAML frontmatter（`name`／`description`）+ 流程 | 用通用辦法做專業活 |
| 5 | **可選面板** | 寫在場景配置裡 | `type` 決定渲染器；**會話面板必須綁 `sessionId`** | 只能靠聊天，效率低 |
| 6 | **常駐會話 + 身份索引一行** | `_場景身份索引.md` 的一行 | 七欄，見第 5 節 | 引擎不注入身分 ⇒ agent 會猜，一猜就串台 |

> ★ **②③⑥ 是不可省的三件**（①④⑤ 可以退化成「共用」）。
> 判斷一個場景「成不成立」，就看這三件有沒有：**卡（職責）、記憶（進度）、索引（身分）**。

### 體量紅線（每個對象都有門檻）

| 對象 | 紅線 | 超了怎麼辦 | 擋還是警 |
|---|---|---|---|
| `§〇` 交接段 | **4 096 B（4 KB）** | 歷史搬進 `歸檔/`，只留最新一份 + 指針 | **擋**（exit=1） |
| `場景私有記憶.md` 主檔 | **25 600 B（25 KB）** | 舊輪次、舊決策搬進 `歸檔/` | 警 |
| `專案記憶/<專案id>.md` | **8 192 B（8 KB）** | 拆成「主檔 + 附錄」 | 警 |
| 單篇技能 | 12 KB | 拆成「主檔 + reference 子檔」 | 慣例（無工具檢查） |
| 定位卡指紋長度 | 16 碼 | —— | —— |

> 紅線是**位元組數**，不是行數也不是字元數——同一段中文在不同工具下算出的字元數差異很大，
> **只有位元組是穩定的**。紅線數字的定義位置見[二-交接與校驗](二-交接與校驗.md)第 2 節。

## 3. 場景私有記憶.md 規格

```markdown
# <場景名> · 場景私有記憶

> 身份與形態見 `身份卡.md` / `場景畫像.md`（工具生成，⛔ 手改）
> 規矩：這份記憶只有本場景能改寫；別的場景發現錯誤只能提醒。

## §〇 當前交接（≤4 KB，新會話先讀這一節）

### 1) 上次交接
- <做了什麼 / 結果 / 證據>

### 2) 當前專案
| 專案 | 記憶檔 | 狀態 | 下一步 |
|---|---|---|---|
| <專案名> | <專案id>.md | 進行中 | <動作> |

### 3) 私有記憶變更
- <YYYY-MM-DD>：<改了什麼 + 為什麼>

### 4) 下一步 / 卡點
- 下一步：<誰先動，按什麼順序>
- 卡點：<沒有就寫「無」；有就寫清等誰>

### 5) 全貌
- 專案記憶 N 個 · 歸檔 M 份 · 索引 _檔案索引.md
- 身份卡 / 場景畫像 / 共享層 areas 已就位
- 卡點 / 等誰：見第 4 節

## 核心職責

- 負責：<用一句話說清「什麼事找我」>
- 不碰：<用一句話說清「什麼別找我」>
- 一句話：<能不能一句話說清這個場景為什麼存在>

## §一 我管什麼 / 不管什麼

- 管：
- 不管：

## §二 幹活入口

- 專案記憶：`專案記憶/<專案名>.md`（索引表放上面 §〇 第 2 小節）
- 歸檔：`歸檔/`
- 索引：`_檔案索引.md`

## §五 決策與坑（只追加）

## 〇-通知
```

### 各段的契約

| 段 | 契約 | 紅線 |
|---|---|---|
| `§〇` | **覆蓋寫**，只留最新一份 | **≤ 4 KB**（硬，超了擋） |
| `核心職責` | ≥ 3 條（負責／不碰／一句話） | 缺一即報錯 |
| `§一 §二` | 職責邊界與入口 | —— |
| `§五` | **只追加**，不改歷史 | —— |
| `〇-通知` | 跨場景留言落點 | —— |
| 整個主檔案 | —— | ≤ 25 KB（超了搬 `歸檔/`） |

> ⚠️ **`§〇` 只回答四個問題**：我是誰／幹到哪／下一步／卡在哪。
> 寫成週報是最常見的錯法。

### §〇 五小節的逐節判據

「五小節齊備」是**機械檢查**（缺一即擋，exit=1）；
但「每一小節有沒有真的回答它該回答的」是**人工判據**。兩者都要過。

| 小節 | 回答的問題 | 判據（寫完自己對一次） | 寫壞了的樣子 |
|---|---|---|---|
| **1) 上次交接** | 上輪幹到哪、產出了什麼 | 有**可點開的路徑**，不是「做了很多事」 | 「今天做了 1、2、3、4、5 件事」（⇒ 變週報，會超線） |
| **2) 當前專案** | 現在手上有哪些活 | 每列都有**記憶檔路徑 + 狀態 + 下一步** | 空表 |
| **3) 私有記憶變更** | 記憶本身改了什麼、為什麼 | 每行有**日期 + 改了什麼 + 為什麼** | 只寫「更新」 |
| **4) 下一步 / 卡點** | 新會話第一個動作是什麼 | 「下一步」與「卡點」兩行都要有；卡點要寫**等誰** | 留空（⇒ 工具會警告「第 4 小節 下一步/卡點 為空」） |
| **5) 全貌** | 這個場景整體長什麼樣 | **工具生成**；數字（專案記憶 N 個、歸檔 M 份）要對得上 | 手動編數字 |

### 寫回判據（每一次寫進記憶都要過這張表）

| ✅ 記 | ⛔ 不記 |
|---|---|
| 建／改了一個應用、修了一個 bug | 搜尋結果 |
| 寫了一份報告／文件 | 臨時路徑 |
| 重構／架構變更 | 工具報錯原文（要記就記「症狀 → 根因」） |
| 選定了一個技術方案 | 一次性約束（「這次先這樣」） |
| 機主分享的約定 | 聊天過程 |

**量**：每次寫回 **≤ 10 行 / ≤ 2 KB**。
**判據**：「三個月後我還會需要這一行嗎？」不需要就別寫。

### 減肥的硬要求：只搬不丟，而且必須能證明

```
① 先存一份「搬之前」的快照          ← 沒這步，後面無法證明沒丟東西
② 搬（歷史 → 歸檔/）
③ 跑核對腳本：逐行比對「搬前非歷史行 == 搬後非歷史行」
      命中 0 差異 ⇒ 才算沒丟
④ 跑索引體檢：死條目 / 未登記 / 過期 / 身分漂移
```

> **真實教訓（實測，2026-10-31）：**
> 有一次沒存快照就動手拆，結果**核對腳本根本跑不了**——
> 你無法證明自己沒丟東西。
> 從那以後規矩改成：**先快照，再動手。**

### 實測：紅線邊界在哪（2026-11-01）

| 實測值 | 數字 | 說明 |
|---|---|---|
| 示範場景 §〇 | **587 B** | 紅線 4 096 B，餘量 3 509 B |
| 示範場景主檔 | **1 375 B** | 紅線 25 600 B |
| 恰好不超線的最大 §〇 | **4 089 B** | 187 列填充；再多一行 4 109 B ⇒ 超線 |
| 本機三場景 §〇 實測 | **4 012 / 4 047 / 1 693 B** | 其中兩個**距紅線不到 100 B** |

> ⚠️ 紅線只在「超過」時才擋，**不會提前警告快滿了**。
> 定期量一下 §〇 大小，近線就減肥——不要等它某天突然全紅。

## 4. 定位卡規格

```markdown
# <場景名> · 定位卡

- 場景 id：`<場景id>`
- 場景名：<場景名>
- 面板：<面板路徑>
- 記憶目錄：場景/<場景名>/
- 專屬技能：`<場景id>`（`場景/<場景名>/.dsh/skills/<場景id>/SKILL.md`）
- 定位卡版本：1
```

> **定位卡是校驗的錨點**：工具會把它的 sha256 前 16 位寫進 `身份卡.md`。
> 改了定位卡但沒重蓋身份卡 ⇒ `check` 報「卡指紋過期」。

## 5. 身份索引規格

**單一權威**，所有「場景 ↔ 會話 ↔ 定位卡」的對應都在這一張表：

```markdown
## 二 · 場景身份索引

| 場景id | 面板id | 面板標題 | 會話名 | 會話id | 定位卡 | 主技能 |
|---|---|---|---|---|---|---|
| `sc-a` | `sc-a-ai` | 場景甲 | 場景甲 | `session-xxxx` | `場景/場景甲/定位卡.md` | `command` |
```

> ⚠️ **這張表被搬過位置時，工具裡的索引路徑必須同步改**——
> 這是一個已發生過的真實事故（見[四-已知裂縫與待修](四-已知裂縫與待修.md)第 4 條）。
>
> **修法不是「記得改」**，是**讓索引路徑也走候選鏈**：
> ```
> 場景/_場景身份索引.md
>   → 外壳/scenarios/_場景身份索引.md
> ```
> 取第一個存在的。搬位就不會讓工具全盲。

### 七欄各自的用處（少一欄會出什麼事）

| 欄 | 誰在用 | 缺了會怎樣 |
|---|---|---|
| 場景 id | 工具（比對場景 json） | 工具找不到場景 |
| 面板 id | 派單／通知／刷新面板 | 別的場景喊不到你 |
| 面板標題 | 人看的 | 無傷，但你自己會認錯 |
| 會話名 | 引擎按名字找會話 | **會話綁定失效 = 切場景時串台** |
| 會話 id | 引擎按 id 精確找（**唯一權威**） | 同上；換會話後不同步就指到舊會話 |
| 定位卡 | 該場景的職責／資產／進度 | AI 不知道自己該幹什麼 |
| 主技能 | 該場景的專業流程 | AI 會用通用辦法硬幹專業活 |

> ⚠️ **表與場景 json 不一致 = 表過期，不是 json 錯。**

## 6. 專案記憶規格

一專案一份，**≤ 8 KB**，欄位固定：

```markdown
# <專案名>

- 狀態：<進行中 / 已完成 / 待接手>
- 一句話：<這個專案在做什麼>
- 成果證據：<檔案路徑 / commit / 數字>
- 下一步：<誰先動，做什麼>
- 坑：<踩過的坑，只追加>
- 已有檔案：<相關檔案清單>
```

> **專案記憶歸場景所有**，不是共享層的東西——
> 一個專案結束了，**場景還在**（見[`二-場景體系`](../00-核心機制/二-場景體系.md)第 1 節的場景／專案對照）。

**路由**：共享層 `_共享記憶/項目.json` 的 `memory` 欄位指到這個檔案。
**一份專案記憶只對一個路徑**——有兩處指向同一份就會分叉。

## 7. 檔案索引規格

```markdown
# <場景名> · 檔案索引
```

## 8. 命名約定

| 對象 | 約定 | 例子 |
|---|---|---|
| 場景目錄 | 中文名，不帶符號 | `場景/場景丁/` |
| 場景 id | 英文小寫 + 連字號，只允許 `[a-z0-9-]+` | `sc-d` |
| 記憶主檔 | `場景私有記憶.md` | 固定名，不可改 |
| 專案記憶 | `<專案id>.md`，id 英文 | `磁碟體檢-2026-10-31.md` |
| 歸檔快照 | `<主檔名>-<時間戳>-<會話前6碼>.md` | `場景私有記憶-202610311007-a93204.md` |
| 工具腳本 | 動賓詞 | `場景記憶.mjs`、`建會話.mjs` |

> **場景目錄名與場景 id 要分開**：目錄名給人看（中文），id 給機器看（英文）。
> 工具兩邊都支援，別只記其中一種。

### ⚠️ 一個真實踩過的坑：以為是硬連結，其實是兩份檔案

**實測（2026-11-01，本機工作台）**：

```bash
stat -c 'inode=%i links=%h  %n' 場景私有記憶.md <場景名>場景私有記憶.md
# inode=5636724 links=1  場景私有記憶.md
# inode=5374645 links=1  場景丙場景私有記憶.md
```

| 事實 | 數值 | 意義 |
|---|---|---|
| 兩個檔案的 inode | **5636724 vs 5374645** | ★ **不同 inode ⇒ 不是硬連結** |
| 連結數 | **兩者都是 1** | 每個檔案各自只有一個名稱指向它 |
| 內容差異 | 主檔有最新進度；副本還是空骨架 | **兩份已經分叉了** |

> ⚠️ **「看起來是同一份」不代表是同一份。**
> 兩份檔案各自被寫，久了內容就不一樣了——
> 而且**沒有任何錯誤訊息**，你只會在讀到舊內容時覺得「怎麼回到舊狀態了」。
>
> **修法**：⛔ 不要假設副本會同步。要嘛**只用一個檔案**，
> 要嘛真的建立硬連結（`ln`）並且**驗證連結數 > 1**。
> 驗證成本是個 `stat`，不驗證的成本是「讀到舊內容還不知道」。

## 9. 跨場景留言（不叫醒對方的那條通道）

檔案留言是**零網路請求**的投遞方式——對方不醒著也能收。

```
- [2026-10-31 09:12] → <場景名>：【派單·請回執】<一行摘要，細節看共享看板>
```

| 特性 | 說明 |
|---|---|
| 零網路請求 | 純檔案寫入，對方不醒著也能收 |
| 只能等回執 | 沒辦法主動確認對方看過了 |
| **必須雙寫** | 共享看板 + 收件方的 `## 〇-通知` |

> ⚠️ **雙寫是「看板分裂」的來源。**
> 兩個腳本寫到不同路徑時，收件方根本收不到，而表面完全看不出來。
> 修法是**統一路徑解析**，不是「記得寫兩邊」——
> 見[四-已知裂縫與待修](四-已知裂縫與待修.md)第 3 條。

## 10. 拿到規格之後怎麼確認自己沒有漏

```bash
# ① 一覽：每個場景缺哪一件（含邊界 .git 有沒有）
node 03-可執行工具/場景記憶.mjs list --root <工作台根>

# ② 逐場景：結構/邊界/指紋/§〇/專案/歸檔 全檢
node 03-可執行工具/場景記憶.mjs check --場景 <場景名> --root <工作台根>

# ③ 全場景一次過（退出碼 0 = 全過，1 = 有場景沒過）
node 03-可執行工具/場景記憶.mjs check --all --root <工作台根>

# ④ 證明這個檢查器是真的（故意弄壞 10 種情況）
bash 03-可執行工具/反例驗收.sh
```

| 場景甲 | 對應本文的哪一節 |
|---|---|
| `list` | 第 2 節（場景目錄規格） |
| `init` / `stamp` | 第 3、4 節（記憶檔、定位卡、身份卡格式） |
| `交接` | 第 3 節（§〇 覆蓋寫、歸檔快照） |
| `check` | 第 2 節的紅線表 |

> 逐條訊息與退出碼見 [`03-可執行工具/讀我.md`](../03-可執行工具/讀我.md)；
> 「該失敗時會失敗」的驗收方法見 [`二-交接與校驗`](二-交接與校驗.md)第 6 節。
