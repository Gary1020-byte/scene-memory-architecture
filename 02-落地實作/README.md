## 一句話

> **規格是給人抄的，校驗是給機器守的，維護手冊是給未來的你看的。**

---

## 這四篇怎麼串起來

```
一-目錄與檔案規格  ──定形狀──▶  二-交接與校驗  ──守規矩──▶  三-維護手冊
      （長什麼樣）              （怎麼確認沒壞）            （壞了/要改了怎麼辦）
         │                                                     ▲
         │                                            五-新增場景規範
         │                                        （新增是另一種「改了」）
         ▼                                                     │
四-已知裂縫與待修 ─────────────────────────────────────────────┘
  （這就是「要改了」的理由來源）
```

**八-內容到鏡頭規格** 是第一條**有實測案例的落地鏈**：
```
content.md（唯一真源）
   ├──▶ 線 A · OpenDesign ──▶ 報告／簡報 HTML
   └──▶ 線 B · 旁白 ──▶ beats ──▶ compositions ──▶ MP4 ──▶ REVIEW
```
> ★ 兩條線共用**素材與 token**，**不互相轉換**（轉換會有損）。
> ★ 最容易踩空的一條：**`check` 全綠不代表沒問題** —— 順序錯、疊在一起，check 抓不到。

**六-歸檔層 ＋ 七-換會話** 是另外兩件事：
```
六-歸檔層  ──管「聊天全文去哪」──▶  會話檔案/ + 索引（可 grep）
七-換會話  ──管「怎麼把身分換掉」──▶  四步 + 三處同步 + 機械自檢
      │                                    │
      └──── 換會話時順便把舊會話落檔 ◀────┘
```

> **五-新增場景規範** 特別值得先看：它把「開一個新場景」變成**十步、每步有機械驗收**的流程，
> 而且揭露了三個「症狀不明顯」的坑（忘了 `git init`、sessionId 只填一處、改了定位卡沒重蓋）。
