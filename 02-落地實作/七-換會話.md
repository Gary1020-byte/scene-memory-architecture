# 七 · 換會話：一條可重複、有自檢的原子操作

> **「換會話」必須是一條場景甲，不是一套讓人背下來的手工流程。**
> 因為只要有一處沒做（舊會話沒真歸檔、三處沒同步），下次開場就對不上號——
> **而症狀全都一樣**（「切到這個場景，AI 像換了個人」），根因卻不同。
>
> 這篇把它變成：**前置檢查 → 四步 → 機械自檢**。

---

## 一、什麼時候該換

| 情形 | 該不該換 |
|---|---|
| 看到上下文壓力到線（工具報的百分比、⚠ 之類） | ❌ **不該**。到線會自動壓縮���任務可以繼續做完 |
| 壓縮之後**仍然**報「上下文超限／413 之類的硬錯誤」 | ✅ 該換（真死鎖了） |
| 使用者明確說「換會話／歸檔並新建」 | ✅ 該換（使用者說了算） |
| 只是「覺得會話有點長了」 | ❌ 別換——中途換會話＝把沒幹完的活扔給下一條會話 |
| 場景換題目了 | ✅ 該換（舊題目的上下文對新題目是干擾） |

> **判據只認「當場跑出來的那一行」壓力輸出。**
> 交接文件／摘要裡的歷史數字只屬於寫它的那條會話，不能拿來判斷現在。

> **「到線會自動壓縮」是引擎行為，不是這套方法論保證的。**
> 換引擎時要重測這件事——見[三-維護手冊](三-維護手冊.md)任務 E。

## 二、四步

```
① 先把交接寫好        ← 這一步就是交接，別省
   覆蓋寫 §〇 的「進度 / 下一步 / 卡點」
   （寫不出「下一步」＝ 這輪白幹了）

② 新建會話 + 舊會話歸檔     ← 引擎端
   新會話：同名、cwd＝場景目錄
   舊會話：改名成「已歸檔 · <原名> · <日期>」＋ **真歸檔**

③ 同步三處                  ← ★ 引擎端做完立刻做
   ① 場景配置 json 的 sessionId
   ② 身份索引表的會話 id 欄
   ③ §〇 的交接署名

④ 自檢                      ← 跑工具
   node 換會話.mjs 檢查 --root <根> --場景 <名> --新會話id <id>
```

### 2.1 第 ① 步：交接是前置條件，不是事後補的

**記憶在檔案裡，不在會話裡。** 沒有交接的換會話＝記憶斷檔。

| 漏了 | 症狀 |
|---|---|
| 沒寫 §〇 就換 | 新會話開場是空白，不知道上一輪幹到哪 |
| §₀ 寫成週報 | 撐爆 4 KB 紅線，而且新會話读完仍然不知道下一步 |

### 2.2 第 ② 步：「改名 ≠ 歸檔」（最容易踩的一個坑）

這是實測出來的、**兩種結果長得一樣但機制完全不同**的坑：

| 只改名 | 真歸檔 |
|---|---|
| 標題變成「已歸檔 · X · 日期」 | 標題變了 **＋ 從列表裡消失** |
| **它還掛在列表裡**，使用者下次還會點進去 | 列表裡沒有它了 |
| 以為歸檔了，其實沒歸檔 | 真的歸檔了 |

**引擎沒有 `session/archive｜delete｜remove｜trash`（全 404）。**
歸檔＝**改名 ＋ `workspace/archiveSession`**（有活動時帶 `stopActivity` 重試）。

> ★ **自己歸檔自己永遠只成功一半。**
> 引擎拒絕歸檔一條「正在跑」的會話（它此刻正在跑這輪）⇒ 結果只改了名字。
> **正解是從另一條會話／腳本裡歸檔它。**
>
> 這也是為什麼換會話要是一條場景甲而不是手工流程——**手工流程人就在那條會話裡。**

#### 引擎端的兩個實測結論（2026-11-03，DSH）

| 問題 | 實測結果 | 結論 |
|---|---|---|
| 歸檔後舊會話還在 `session/list` 裡嗎 | **在** | `archivedSessionIds` 只影響 **UI 側邊欄**，不影響 `session/list` |
| 能把舊會話從 workspace 的 `sessionIds` 移除嗎 | **不能**（改了引擎就加回去） | 那是對的——舊會話確實屬於該工作區，只是被歸檔了 |
| 新會話要自己釘嗎 | **要** | 不釘 ⇒ 面板找不到它 |

> **★ 「舊會話還在 session/list」不是 bug。** 會話仍在磁碟上、仍可讀，
> 只是不再出現在側邊欄。**歸檔不是刪除**——這正是它該有的性質。

### 2.3 第 ③ 步：三處，不是「兩處加備忘」

| # | 位置 | 誰寫 |
|---|---|---|
| ① | 場景配置（面板 json）的 `sessionId` | 引擎端 |
| ② | 身份索引表的會話 id 欄 | 引擎端 |
| ③ | §〇 的交接署名 | 人／工具 |

> **少同步任何一處的症狀都一樣**（切場景像換了個人），**但根因不同**——
> **所以要三處一起對，不要靠症狀去猜是哪一處漏了。**
> 這就是 `換會話.mjs 檢查` 存在的理由。

**§₀ 交接署名的格式**（寫進 `交接規則.json`，不在程式裡另寫）：

```
本交接由會話 <sessionId> 於 <日期> 改寫
```

### 2.4 第 ④ 步：自檢是機械的

```bash
node 03-可執行工具/換會話.mjs 計畫 --root <工作台根> --場景 <場景名>
node 03-可執行工具/換會話.mjs 檢查 --root <工作台根> --場景 <場景名> --新會話id <id>
```

`計畫` = 前置檢查（能不能換）＋ 印出引擎端要做的五步 ＋ 印出三處同步位置。
`檢查` = 換完的機械驗收（三處一致 ＋ `check` 通過 ＋ §₀ 沒超紅線）。

## 三、工具

### 3.1 `計畫` 擋什麼

| 檢查 | 不過就擋 |
|---|---|
| 場景目錄存在 | ✅ 擋 |
| §₀ 五小節齊 | ✅ 擋 |
| §₀ 有可讀的「下一步」 | ✅ 擋 |
| §₀ 現在就沒超紅線（換會話要寫署名，只會更大） | ✅ 擋 |
| 讀得到身份索引的卡 | ⚠ 警 |
| 讀得到場景配置的 sessionId | ⚠ 警 |

> ★ **「§₀ 沒有下一步」是硬擋。**
> 換會話等於把活扔掉——**寫不出下一步，說明這輪還沒結束，那就不該換。**
>
> ★ **「§₀ 換會話後會超紅線」也是硬擋。**
> 因為換會話要寫交接署名（多幾十字）⇒ 已經貼線的 §₀ 會在換完當下爆紅線，
> 而那時新會話已經建好了，**要退回來重來**。
> 所以要在換**之前**就擋。實測：場景丁的 §₀ 原本 4068 B，
> 換完變 4156 B ⇒ 超紅線 ⇒ 必須先把歷史搬進 §五再換。

### 3.2 `檢查` 擋什麼

| 檢查 | 不過就擋 |
|---|---|
| §₀ 五小節齊 | ✅ 擋 |
| §₀ 有下一步 | ✅ 擋 |
| 三處都有會話 id | ✅ 擋 |
| 三處是**同一個** id | ✅ 擋 |
| 指定 `--新會話id` 時三處都等於它 | ✅ 擋 |
| §₀ ≤ 4 KB | ✅ 擋 |
| `場景記憶.mjs check` 通過 | ✅ 擋 |

### 3.3 為什麼「缺一處」也算不一致

少同步一處的**症狀跟同步錯了完全一樣**。
所以檢查邏輯是：**三處都必須有值，且必須是同一個 id**——不是「有值的那幾處一致就好」。

## 四、零散會話（沒有場景面板的那些）

不在場景表裡的會話沒有「面板 id」可填，但同樣需要交接。
做法是：**一份臨時交接文件 ＋ 同一條場景甲**（用會話名而不是場景名）。

> **結論：「換會話」是一個可重複的、有自檢的原子操作**，
> 不管這條會話有沒有場景。

---

## 五、分叉，而不是新建

如果只是「這一段太長，但前半段的成果想留著」，可以從**較早的一條訊息**上分叉：
分叉只帶走分叉點之前��歷史——相當於「把前半段搬進新會話」。

| | 換會話 | 分叉 |
|---|---|---|
| 帶走多少歷史 | 一點都不帶 | 分叉點之前的全部 |
| 適合 | 換腦、換題目 | 任務做一半、上下文太滿 |
| 一樣要做 | 回寫三處 ＋ 自檢 | 回寫三處 ＋ 自檢 |

> 分叉完**新會話是新的 id**，所以三處一樣要同步、一樣要自檢。

---

## 六、什麼時候要真的「歸檔」到檔案

換會話＝把**身分**換掉；舊會話的**聊天全文**另有一個去處——
那是[六-歸檔層](六-歸檔層.md)，不是這篇。

```
換會話  ⇒  舊會話離場（引擎端歸檔）
           ＋ 聊天全文落到 會話檔案/（工具做，見歸檔層）
```

> **兩件事一起做才完整。** 只換會話不落檔，聊天全文就只剩引擎裡的黑盒子——
> 而引擎會改版（實測：23/30 條已經讀不動了）。

## 七、常見錯誤

| 症狀 | 根因 | 修法 |
|---|---|---|
| 舊會話改名了但還在列表裡 | 只改名沒真歸檔 | 從**另一條**會話／腳本跑 `workspace/archiveSession` |
| 切場景像換了個人 | 三處沒同步 | 跑 `換會話.mjs 檢查`，看它報哪一處 |
| 新會話開場是空白 | 沒寫 §₀ 就換了 | 先寫 §₀ 再換 |
| 換完 `check` 全紅 | 換會話把記憶檔結構弄壞了 | `場景記憶.mjs 交接` 補 §₀ 小節（缺才補） |
| 自己歸檔自己只成功一半 | 引擎拒絕歸檔正在跑的會話 | 從外部歸檔 |
